# Style, cascade and values

[Architecture index](README.md)

Implementation notes for people changing Nile: Parsing, the cascade, restyling, themes, fonts, scrollbars and the modern CSS mechanisms. Each note says where the code is and which trap it avoids. They are kept as written while the code was built, so check a name against the source before relying on it.

- Partial restyle (`View::restyle_after_state`, `StyleMap::recascade`): a hover/active/focus change cascades again only the subtrees of the elements whose state changed (`StateDeps::sibling`: their parents', when a rule has a state selector followed by `+`/`~`), in place, with `ElementRef` matching the new `InteractionState`; with transitions set up (`View::base`) the targets are recascaded and `Animator::update_nodes` starts transitions for those nodes only. It falls back to the full `restyle` when the DOM changed, generated `::before`/`::after`/`::marker` content exists, or the new rules start animations on a page that had none. Parsed sheets are cached per thread (`sheets_of`), so even a full restyle doesn't re-parse CSS. `restyling_after_a_state_change_matches_a_full_cascade` checks the result equals a full cascade; `bench_hover` (ignored): 1,500-row page, ~15 ms -> ~0.2 ms per pointer move. `transition-property` shorthands (`background`, `margin`, `border-color`...) now cover their longhands.
- Restyle without relayout: `View::restyle`/`animate` compare the old and new `StyleMap` with `StyleMap::same_layout` (a `ComputedStyle` clone with the paint-only fields copied over, then `==`). If only paint properties differ and the DOM didn't change, the `LayoutTree` is kept and `refresh_paint` re-bakes transforms. Text `color` counts as paint-only too (`same_layout_with`): the renderer takes it from `styles` via `TextContent::owners` instead of the shaped brush, except for control text and pages with generated `::before`/`::after` content; inline elements keep background/border changes layout-affecting because those are baked into the text run (`InlineDeco`). `StyleMap::state_deps` says which of `:hover`/`:active`/`:focus` any selector mentions; `Page::set_interaction` skips the restyle when the changed state isn't one of them. When you add a `ComputedStyle` field that layout never reads (and that isn't baked into `LayoutBox`/`TextContent`), add it to `same_layout`; otherwise leave it out. `NILE_TRACE=1` prints style/layout/paint/animate timings (`traced` in the shell); `examples/stress.html` is the 1,500-row benchmark page. `cursor` is inherited and mapped to winit's `CursorIcon` by `App::sync_cursor`.
- `width: fit-content|max-content|min-content` is `ComputedStyle::width_fit` (min-content is treated as max-content): `build` measures the node at max-content and sets its width (content-box adjusted by padding/border) with `max-width: 100%` unless one is set; block/flex/list-item only. The UA `legend { width: fit-content }` relies on it (the `border_gap` notch is the legend's box).
- `::marker`: parsed as `PseudoElement::Marker`, cascaded per list item into `StyleMap::markers` (`MarkerStyle`: style, optional colour, optional `content`), not into boxes; `build_markers` uses it, and `ListMarker::color` is only set when the rule sets a colour (otherwise the item's live colour is used so paint-only restyles stay correct). `list-style-position: inside` adds `inside_marker_width` to the item's left padding in `taffy_style` and draws the marker at the content edge.
- `border-radius` is `Corners` (px, clockwise from top left) plus `border_radius_pct` (fractions of the box's width/height); the renderer resolves both through `ComputedStyle::corner_radii(w, h)` into Skia's per-corner radii (`round_rect`). Inline decorations (`InlineDeco`) keep one uniform radius.
- Web fonts and `@supports`: `Stylesheet::font_faces` (`parse::FontFace`: family, `url(...)` list, weight/italic) -> `StyleMap::font_faces`; `register_fonts` (nile-layout, start of `layout_with`) reads each face's first loadable source through `ImageLoader::bytes` (`FileImages` reads files, `data:` URLs and the packed archive) and `TextEngine::register_font` (nile-text: WOFF/WOFF2 decoded by `wuff`, then fontique `register_fonts` with the family name as an override, each source once). `font-family` now keeps the whole list (quoted when a name has spaces) so a missing family falls through. `@supports` conditions (`parse::supports_matches`: `not`/`and`/`or`/parentheses/`selector()`) test property *names* by running the declaration through `apply`, which sets `UNRECOGNISED` when its catch-all arm doesn't know the property. Not done: `local()`, `unicode-range`, `font-display`, fonts from http, a stylesheet's relative font URLs resolve against the page.
- Style sheet files: `nile_dom::inline_links` (`nile-dom/src/stylelink.rs`) runs next to `<include>` in `Page::from_source_in` and replaces `<link rel=stylesheet href media>` with a `<style data-href>` holding the file (media becomes an `@media` wrapper) and inlines `@import`s relative to the importing file (depth 8); a link added by script isn't loaded and `url()` in a sheet is relative to the page, not the sheet.
- `<include src media>`: `nile-dom/src/include.rs` expands it as *text* before parsing (so it works in `<head>` too); `Page::from_source` supplies the loader (files under the page's folder; a nested `src` is relative to the fragment naming it). A missing fragment or false `media` (`platform == "OSX"`, `!=`, `and`/`or`) keeps the element's own content as the fallback; depth limit 16 stops cycles.
- Style values: `parse.rs` evaluates `@media` and `vw`/`vh` at parse time against the viewport
  (`compute_styles_in`; `StyleMap::uses_viewport` tells the shell to restyle on resize). Custom
  properties and `var()` keep the source text in `Declaration::raw` and are resolved per element in
  the cascade (`substitute`). `!important` is a stable sort of the collected declarations.
  `examples/css-compat.html` is the visual conformance page; green = works. `calc()` mixing `%` and
  `px` becomes `Length::Calc` and is resolved by `resolve_calcs` in layout after a first pass (Taffy's
  own calc hook is a stub in `TaffyTree`). Animation: the cascade yields target styles (`ComputedStyle::{transitions, animations}`, `StyleMap::keyframes`); the shell's `View` keeps them as `base`, owns an `Animator` (nile-style/src/anim.rs) and a clock, and overwrites `styles` with in-between values on each restyle (`adopt`, starts transitions) and each 16ms tick (`animate`) while `Animator::is_active`. Times are seconds; tests call `Animator::update` with explicit times. `transform` becomes `LayoutBox::transform` (an `Affine` in layout coordinates with the origin folded in); `placements()` composes it with scroll translations into `Placement::xf`, which hit testing, `node_rect_scrolled` and text-index lookups use, and the renderer `concat`s it around the box's subtree. Never read scroll shifts as plain dx/dy any more. Images: the embedder gives layout an `ImageLoader` (`LayoutOptions::images`; the shell uses `FileImages` on the page's folder). Layout only needs sizes (`imagesize`), loads what the document and styles name up front into a thread-local, and puts the encoded `ImageData` on `LayoutBox::{image, bg_image}`; the renderer decodes with Skia and caches by `ImageData::id`. `<img>` is a `NodeCtx::Replaced` Taffy leaf. Grid properties live in `nile-style/src/grid.rs` (`Value::{Fr, Slash, Minmax, Repeat}` from the parser; `grid-area` names resolved to line numbers in layout's `place_in_area`); layout maps them straight onto Taffy's grid style. Absolute boxes are re-parented in the Taffy tree to their nearest positioned ancestor (`with_containing_block`/`hand_off_absolute`, thread-locals in `nile-layout`; the root is the fallback), and `flatten` sorts siblings into paint order by `z-index` (`paint_layer`). Gradients are `Value::Gradient` -> `ComputedStyle::background_image` (stops resolved by `Gradient::resolved_stops`); the renderer's `gradient_shader` builds the Skia shader. `::before`/`::after` are "generated boxes": the cascade (`pseudo_style`, matched in `ForStatelessPseudoElement` mode) appends their styles to `StyleMap::styles` under ids past the document's nodes, with `StyleMap::{pseudo, origin, content, is_pseudo}`. Layout's `kids()` puts them around an element's children; `hit_test` and text owners map back to the element, and `node_rect`/the index skip them. Never call `doc.node()` on a box id without checking `styles.is_pseudo`. `opacity < 1` wraps the element's paint-list range `[i, subtree_end)` in a `save_layer_alpha`. Borders are per side (`border_color`, `border_style`,
  `border_width`); `border_color_set` holds what the author set, `None` = currentColor.

- Modern CSS mechanisms (2026-10-18): `ComputedStyle::layered()` (filter, blend, mask, `clip-path`, isolation) is part of `forms_context`/`confines`/`paint_layer` like `opacity`, so the renderer's per-box `Close` stack (`nile-render`) can wrap the subtree in a layer (image filter + blend mode), a `clip_path` save and a mask drawn with `DstIn` when it ends; `backdrop-filter` is a `save_layer` with a backdrop right before the box paints. `filter`/`backdrop-filter`/`clip-path` keep their text (`keeps_raw`) and are parsed by `effects.rs` / `shape.rs`. `visibility`/`pointer-events` are inherited fields; `LayoutBox::inert` makes hit testing pass through. `order` sorts the children in `ordered()` (flex/grid only). Text: `TextStyle` carries word spacing/break/overflow-wrap/decoration into Parley and the brush; `text-indent` and inline margins are leading/trailing spacer runs (a 1px NBSP stretched with letter spacing, so a big spacer never makes the line taller); `-webkit-line-clamp` and `text-wrap: balance` live in `NodeCtx::Text::flow` (`clamped_height`, `balanced_width`; the renderer draws the ellipsis). Counters are walked during the cascade (`Generated::counters`, scoped to the parent's subtree). Parser: `logical()` maps logical properties to physical ones in `apply`; CSS nesting is text-level (`split_body`/`add_rule` build combined selectors), `@layer` is `Rule::layer` ordered before specificity; `color.rs` holds the colour spaces and `color-mix`; `Value::LightDark` resolves through `system::current_dark()` when applied; `fold_math` folds the `calc()` functions. Scroll snap: `View::snap_points`/`snap_settle`, `Page::snap_due` (settles in `tick` 140 ms after the last wheel).
- System fonts (`nile-text` `system_families`): the font-family list is rewritten before it reaches Parley (`system-ui` and its aliases -> `UI`, `ui-monospace`/`ui-serif`/`ui-rounded` -> per-platform lists; applied where `shape_spans` builds the `FontFamily`). `with_optical_size` sets `"opsz"` = font size for the system UI fonts only (San Francisco, Segoe UI Variable; other fonts shape exactly as before, because even an inert variations list changes run segmentation/kerning); padding spacers and `nbsp_ratio` use the fixed `spacer_variations` (opsz 17) so their width stays linear in size. `expand_font` (nile-style) handles the system font keywords of `font`. The theme sheets set `html`/controls to `system-ui`. A spacer between letters also removes their kerning, which is why `inline_padding_and_border_take_horizontal_space` uses `sans-serif`.
- System theme (`nile-style/src/system.rs`): `SystemTheme { dark, accent }` per thread (`set_system_theme`/`system_theme`; `NILE_COLOR_SCHEME`/`NILE_ACCENT` override), read by `prefers-color-scheme` (parse time: the author-sheet cache key includes `dark`; JS `N.systemDark`), by `colors::named` (system colour keywords, resolved when styles are computed) and by `ua_sheet(dark_scheme)` (UA + the platform's theme sheet with `@ACCENT@`/`@ACCENT_TEXT@`/`@ACCENT_A@` tokens filled in, cached by theme; `DARK_BASE` + `DARK_<PLATFORM>` are added when `dark_scheme`). `cascade` picks the user-agent sheet per element (`CascadeInput::{ua_light, ua_dark}`, `matching_decls(.., dark)`): it starts from the parent's scheme, applies the declarations, and if the element's own `color-scheme` (`used_dark`: `dark` always, `light dark` = the system's, `light`/`normal` never) differs it matches and applies again; `system::with_scheme` makes system colours resolve in that scheme while the declarations apply. A `<meta name=color-scheme>` is the root element's inherited default (`StyleMap::meta_scheme`). `StyleMap::dark` is the root's scheme (what `palette()` uses; menus, thumbs and the like follow the page, not the element). `ComputedStyle::{color_scheme, accent_color}` are inherited. The renderer's own colours (menus, list rows, progress/range, scroll thumbs, selection) come from `StyleMap::palette()` (`Renderer::pal`); a checked box with `accent-color` is overridden in `paint_box`. `Page::system_theme_changed` restyles a page and its frames; the shell's `App::refresh_theme` (window creation, `ThemeChanged`, focus on macOS/Windows) reads `system::read` (winit theme + platform accent) and calls it. The theme sheets carry `:hover`/`:active`/`:focus-visible` rules (`:focus-visible` = `PseudoClass::FocusVisible`: focused and (`tabfocus` flag or `ElementRef::takes_typing`)), so `StateDeps` is always hover+active+focus and every page does partial restyles on pointer changes; the dark chunks repeat those rules because the light ones out-rank plain dark selectors. Scrollbar thickness and hover growth are per platform (`nile_style::scrollbar_auto/thin/grow`, keyed by `theme_platform()`, so `NILE_THEME` shows them); the default thumb is white-ish in a dark scheme (`paint_thumb`'s `dark`). `MediaQueryList` change events: `matchMedia` lists with a listener are in `watched` (web.js) and re-checked by `__mediaCheck` on window `resize` and from `Page::system_theme_changed`. Not done: a fade-out for macOS overlay bars, Windows' arrow buttons, per-element palettes for engine-drawn menus/thumbs.
- Platform themes: the UA stylesheet is the neutral base plus `THEME_WINDOWS`/`THEME_MACOS`/`THEME_LINUX` (`theme_sheet()` in nile-style, chosen by target OS; `NILE_THEME=windows|macos|linux` overrides it, e.g. for screenshots): buttons, inputs, textareas, selects, checkboxes and radios take the platform's look (Windows 11 Fluent, macOS Aqua-ish with a focus ring, Adwaita-ish), Windows also sets `html`'s font to Segoe UI. Theme rules repeat the base selectors they override (equal specificity, later wins) and have no `:hover`/`:active` (that would make every page restyle on hover).
- Password mask: `nile-password-char` (`ComputedStyle::password_char`, raw text via `keeps_raw`) is recorded per input in layout's `MASKS` thread-local (keyed by document address + node) by `build_control_text`, so `control_display`, `caret_byte` and `caret_char` (which only see the document) agree; the accessibility tree keeps plain bullets.
- Scrollbar styling: `ComputedStyle::{scrollbar_width, scrollbar_color}` plus `PseudoElement::{Scrollbar, ScrollbarThumb, ScrollbarTrack}` (`::-webkit-scrollbar*`) cascaded for scroll containers and `<html>`/`<body>` by `scrollbar_parts` into `StyleMap::scrollbars` (only when some author rule has a pseudo-element); `StyleMap::scrollbar_look(node)` merges them into a `ScrollbarLook` (thickness, thumb, track, radius), `page_scrollbar()` is the page's. Layout puts the thickness in `ScrollBox::thick` (0 = no bar, wheel still works) and `page_thumb(.., thick)`; the renderer's `paint_thumb` takes the look and a `BarState` from `Overlay::bar` (hover grows `SCROLLBAR_GROW`, drag is darker). `Page::bar_hover` is updated by `update_bar_hover` after pointer moves, only when the pointer is in the page's bar strip or over a scroll container (and never builds a layout: the hover-bench test would notice).
- Item-8 odds and ends: `Document::{prev,next}_element_sibling` answer from a per-version index (`siblings`), which `ElementRef` uses; `backface-visibility` is `LayoutBox::backface_hidden` + `Placement::hidden` (`Affine::faces_away`: a negative determinant of the composed matrix, used by `placements`/`hit_test_scrolled` and the renderer's `canvas_faces_away`, which skips the subtree); `:visited` is the `visited` state flag (`click_default` sets it on the link), `:link`/`:any-link` are `PseudoClass` variants; `list-style-image` is `MarkerKind::Image`; `font-variation-settings`/`font-feature-settings` keep their text (`parse::keeps_raw`), go through `TextStyle` to Parley's `FontVariations`/`FontFeatures`, and the renderer's `variable_typeface` clones the Skia typeface at the run's normalized coords (cached in `Renderer::varied`).
- Animation events: `Animator::update` queues `AnimEvent`s (`transitionend`, `animationstart`, `animationend`); `Page::animate` drains them with `take_events` and emits `UiEvent::Animation` (never drain inside `sync`, `emit` calls it).
