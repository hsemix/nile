# Layout and painting order

[Architecture index](README.md)

Implementation notes for people changing Nile: Scrolling boxes, tables, lists, floats, positioning, stacking, transforms and pagination. Each note says where the code is and which trap it avoids. They are kept as written while the code was built, so check a name against the source before relying on it.

- `overflow` boxes: layout gives each clipping element a `ScrollBox` (padding-box
  clip + scrollable extent) and `LayoutBox::subtree_end` marks where its subtree
  ends in the flat paint list. Scroll offsets live in the shell's `View`
  (`scroll_offsets`); `LayoutTree::placements(offsets)` turns them into per-box
  shifts and clips, used by `hit_test_scrolled`, `text_index_at_scrolled` and
  `node_rect_scrolled`, and the renderer applies the same offsets while painting.
  Use the `_scrolled` variants anywhere a pointer or script coordinate is involved.
- Symbol fallback (`nile-text` `is_symbol_gap`, `SYMBOL_FALLBACKS`): characters in U+21B0-21FF, U+2300-23FF, U+25A2-25AF and U+26A0-27BF (on Windows all of U+2190-2BFF) get Apple Symbols / Zapf Dingbats / Segoe UI Symbol / Noto Sans Symbols (2) / DejaVu Sans appended to their font stack; other symbols keep the system's choice. `examples/symbols.html` is the per-font coverage page (run it on Windows/Linux to see gaps).
- Collapsed borders: `resolve_collapsed_borders` (nile-layout, called by `build_table` for `border-collapse`) compares each cell side with the touching cells' sides (`border_strength`: width, then solid > dashed > dotted; the upper/left cell wins ties) and records the sides that lose in the `COLLAPSED` thread-local (cleared per layout), which becomes `LayoutBox::border_hidden`; the renderer's `paint_box` paints those sides as `BorderStyle::None`. Widths and the overlap margins are unchanged (only painting is resolved); `hidden`, `double`/`groove`, row/column/group borders and the table's own border aren't part of it.
- Tables (`build_table`): a table is a Taffy grid with auto tracks. Cells get explicit grid lines from `colspan`/`rowspan`; each `<tr>` becomes an empty grid item behind its cells (so row backgrounds paint); `thead` rows go first and `tfoot` last; `border-spacing` is the gap plus padding, and `border-collapse` zeroes the gap and gives cells negative top/left margins so borders overlap. Taffy's `item_is_table` makes the table shrink-wrap. `caption-side: bottom` puts captions on rows after the last one; a row group whose own style paints gets an empty grid item spanning its rows (`paints_box`), placed before the rows; in an automatic table with a `width` the columns are `minmax(auto, Nfr)` with N = the widest single-column cell's one-line text width plus padding/border. Middle/bottom `vertical-align` wraps the cell's children in an anonymous flex-column node with auto margins (anonymous nodes have no `NodeCtx`, which `flatten` allows).
- Lists and form widgets: list markers aren't boxes. `build_markers` (after flatten) makes a `ListMarker` per `display: list-item` element (`LayoutTree::marker`), numbered by `list_numbers` (`start`/`reversed`/`value`); the renderer draws it left of the item (bullets are shapes, counters shaped text). `<summary>` is a list item with a disclosure triangle, toggled in `Page::click_default`. `<progress>`/`<meter>`/range are `appearance: progress|meter|range` painted by `paint_control_mark` from `ComputedStyle::control_fraction`; range input handling is `Page::range_*`; `<input type=number>` is `appearance: spinner` (arrows painted in `paint_control_mark`, stepping in `Page::number_step`, colour/date/time rules in `nile-engine/src/inputs.rs` (`accepts`, `step`, swatch painted from `ComputedStyle::swatch`), file inputs: a click queues `View::file_request`, the embedder answers `Page::choose_files` (paths live in the internal `nile-files` attribute, JS `files` builds `File`s), arrow hit test `number_arrow_at_pointer`). `white-space` is applied per text node in `apply_white_space`. `text-overflow: ellipsis` is handled at paint time (`TextContent::ellipsis`).
- Inline `vertical-align` (`sub`/`super`/length) is a per-run baseline shift: layout sums `baseline_shift` of the open inline elements into `TextStyle::shift` -> `TextBrush::shift`, and the renderer subtracts it from glyph y and the baseline. It doesn't affect line height.
- `position: fixed`: layout hands such boxes to an anonymous viewport-sized absolute layer (`FIXED_BLOCKS`), marks `LayoutBox::fixed`, and `placements` cancels the page scroll for the subtree using `LayoutTree::page_scroll` (kept current by `View::layout()`); the renderer resets to the base matrix. `sticky` is in-flow (`Position::Sticky`) with `LayoutBox::sticky_shift(scroll, viewport_h)` used by both `placements` and the renderer.
- 3D transforms: `Affine` is a projective 3x3 (`g`, `h`, `i` are the perspective row); `Affine::from_style_in` builds a 4x4 (`M4`) from the `TransformFn` list, folds in the container's `perspective` (`parent_perspective`, stored as `LayoutBox::persp` so `refresh_paint` can re-bake) and flattens it to z = 0. `perspective` changes are layout-affecting in `same_layout` on purpose.
- Static positions: absolute boxes re-parented to a distant containing block are listed in `ABS_HANDED`; `compute_static_positions` (after layout, before `flatten`) turns the ones with `auto` insets into absolute page coordinates in `STATIC_AT`, which `flatten` uses instead of Taffy's (containing-block corner) position.
- Stacking contexts (`flatten`): a context (the root, or `forms_context`: positioned + `z-index`, flex/grid item + `z-index`, `opacity < 1`, `transform`, `fixed`) calls `collect_hoisted` to find the positioned/z-indexed descendants that belong to its paint order, records them in the `HOISTED` thread-local so their ancestors skip them, and emits them around the in-flow children by layer (negative z first, positive last). Descendants beneath a `confines` box (clip, opacity, transform, sticky) are never hoisted, because the flat paint list scopes clips and layers by subtree range. `paint_layer(style, flex_item)` is the single ordering rule.
- `table-layout: fixed`: `build_table` sets `grid_template_columns` (px / % / `minmax(0, 1fr)` per column from `<col>`s, else the first row) and clears the cells' own widths; only when the table's `width` isn't auto.
- Pagination: `ComputedStyle::{break_before, break_after, break_inside}` (`Break::{Auto, Avoid, Always}`, `page-break-*` too); `nile_layout::paginate(tree, styles, page_h)` (`pagination.rs`) returns page start offsets over the one long layout (no cut inside a text line, table row, image or `break-inside: avoid` box that fits a page; orphans/widows of 2; forced breaks first; falls back to lines only, then a hard cut). `@page` is raw text on `Stylesheet::pages`, resolved by `nile-style/src/page.rs` (`StyleMap::page_style(i)`: size, margins, `@top-*`/`@bottom-*` margin boxes with `counter(page|pages)`). `nile-engine/src/paged.rs`: `Page::{paginate, draw_page, render_page, write_pdf}` paint each page by translating the one layout by the page start and clipping (Skia PDF document, 0.75 scale), CLI `--pdf`, `--png --page N`, C `nile_view_write_pdf`. Pagination lays out at the first page's content size and leaves `View::scale` at 1.
- Paged view (`page-view: paged`, `nile-layout/src/paged.rs`): one element shown as sheets. `layout_with` finds the paged elements, `paged::prepare` gives each the paper width and `@page` margins as padding, a first pass + `paginate_boxes` finds the starts, `paged::set_height` makes it as tall as its sheets and a second pass lays out again (starts are kept relative to the element's top). Boxes keep *flow* coordinates; `LayoutTree::pages: Vec<PagedBox>` (`to_screen`, `to_flow(y, strict)`, `page_of_flow`) maps flow <-> where they appear. `Placement::paged` marks every box inside, and `LayoutTree::{to_box, painted, to_layout_rect}` are the only places that apply the mapping: hit testing is strict (margins/gaps hit the element), caret/text lookups lenient (nearest line). The renderer's `paint_boxes` paints a paged element's subtree once per visible sheet (`paint_sheets`: paper with the element's own style, clipped band translated into place, `@page` margin boxes). Editing: `reveal_edit_caret` maps the caret rect; ArrowUp/Down retry past `page_zone_of` when the next line is across the gap. Scripts: `el.pageCount`, `el.pageNumber` (`Environment::page_info`), `execCommand('insertPageBreak')` (`break-before: page` on the new block). Page starts snap to the next line top so the margin before a break isn't carried over. Table headers: `paginate_with` (pagination.rs) finds each `<table>`'s `<thead>` rows (they and their cells are separate boxes in the paint list: groups have none) as a `Repeat` of paint-list ranges, reserves their height on pages that start inside the table, never cuts right after the header, and returns `Fragments { starts, repeats, feet }` (a `<tfoot>` is likewise reserved at the bottom of each page its table goes on from, unless the page ends before the table begins: `drop_foot`; `PagedBox::{feet, foot_h}`, `PagedBox::shown_h` subtracts it, painted at the bottom of the content area by `paint_sheets`/`draw_page`); `PagedBox::repeats`/`head_h`/`shown_h` shift the mapping, the renderer's `paint_sheets` and the engine's `draw_page` paint the ranges at the top of the sheet.
- Text around floats (`plan_floats` in `nile-layout/src/lib.rs`): Taffy gives a text run one slot (the width beside the floats at its top), so after the first compute `plan_floats` flattens once, finds each paragraph (text leaf) whose block formatting context has floats beside it (`own_context`: float, out-of-flow, clipping or non-block boxes between the paragraph and the float's parent keep outer floats out), and re-breaks its lines with `nile_text::break_lines_varying` (Parley's per-line `set_line_x`/`set_line_max_advance`, so glyph offsets, carets and hit tests need no change). The `FlowSpec` (floats relative to the paragraph's top-left, since a second pass can move the group) goes in `FLOW_SPECS` keyed by Taffy node; the leaf gets the new height and Taffy runs again; the final `flatten` breaks with the spec and widens the run's rect to the content box. Float margins count if they are `px`. `shape-outside` (`nile-style/src/shape.rs`: `ShapeOutside::parse` from the declaration's raw text, `Shape::resolve(w, h, shape-margin)` against the reference box, `Resolved::span(y0, y1)` = how far the outline reaches across a line's band) rides on `FloatSpec::shape`: `FlowSpec::slot` pushes a line aside only as far as the outline's reach in that line's band (clipped to the margin box).
