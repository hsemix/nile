# Forms, selection and editing

[Architecture index](README.md)

Implementation notes for people changing Nile: Form controls, text and page selection, rich-text editing, the clipboard, IME, pickers and drag and drop. Each note says where the code is and which trap it avoids. They are kept as written while the code was built, so check a name against the source before relying on it.

- Form controls: `Page` in the shell owns default actions (`click_default`:
  checkbox/radio/label) and text editing (`edit_key`, `caret` in chars of `value`).
  An `<input>`'s text is synthesized in layout (`build_control_text`), the
  renderer draws check/radio marks from `appearance` + `checked` and the caret
  from Parley's `Cursor`. `value` is the `value` attribute; `checked`/`disabled`
  are `Document` state flags. The selection (`anchor`, `caret` in chars of `value`)
  lives in the shared `View` so scripts can read/set it; the renderer highlights it
  from `Overlay::selection`. The clipboard is behind the shell's `Clipboard` trait
  (system via `arboard` with default features off; in-memory for headless/tests).
- `<select>`: `<option>`s are `display: none` in the UA sheet; layout draws the
  chosen label as the select's text and, when `LayoutOptions::menu` is set (from
  the shell's `View::menu`), builds a `MenuBox` that the renderer paints last. The
  shell owns open/highlight/choose (`Page::menu_*`, `select_key`, `choose_option`);
  the choice is the option's `selected` state flag. Changing the menu or scrolling
  invalidates the cached layout.
- Page text selection: `View::page_sel` holds two `TextPoint`s (a text run's index in `LayoutTree::boxes` + byte), valid for one `Document::version`. Layout provides `text_point_at`, `word_at`, `selection_ranges`, `selection_text` (control text and padding spacers excluded); the renderer highlights `Overlay::page_selection`. Pressing on non-focusable content starts it in `Page::begin_page_selection`, but only text whose style has `user_select != None` (the default is *none*, as in desktop UIs; opt-in via `user-select`, a `selectable` attribute (UA rule) or `behavior: htmlarea`; verified against sciter.com docs).
- `<optgroup>`: `select_options` returns option *and* optgroup rows in document order, so every row index (menu highlight, list rows, keyboard) counts headings; `option_disabled` makes a heading a disabled row, which stepping and range selection already skip. A list-box press selects at once (`list_click` from `press`, `list_press` stops the click repeating it) and `list_drag` extends it while the button is down.
- List boxes (`<select multiple>` / `size > 1`, `list_rows`): layout gives the select a fixed height of `size` rows and builds a `ListBox` (rows, scroll) per select in `LayoutTree::lists`; the renderer paints it inline after the box. Its scroll offset lives in `View::scroll_offsets` under the select's id (not a `ScrollBox`). The shell's `list_click`/`list_key` set the `selected` state flags. The drop-down `MenuBox` has its own `scroll`/`max_scroll` and flips above the select when `LayoutOptions::scroll_y` + viewport leave more room there.
- Rich-text editing: `contenteditable` hosts. The *selection* lives in Rust (`View::edit_sel`, two `DomPoint`s: text-node char offset or element child index) so layout can draw and move it; layout maps DOM positions to shaped text through `TextContent::{nodes, marks}` (per text node: char -> run byte, built in `InlineText::collect` by `apply_white_space_mapped`) with `LayoutTree::{text_point_of, dom_point_of, dom_caret_rect, caret_painted, dom_point_at}`. `nile-engine/src/editing.rs` handles what needs layout (pointer placement, Up/Down/Home/End, caret drawing via `Overlay::dom_caret`, scroll-into-view, clipboard keys); everything that edits the DOM is JS in `nile-script/src/edit.js`, spliced into the prelude at `/*@EDIT@*/` (so it shares `N`, `wrap`): `Range`/`Selection`, `execCommand`, typing (`__editKey`, called by `Page::edit_dom_key`), deleting/splitting/merging blocks, inline formatting by wrapping/isolating text nodes (`FORMATS` table), lists, undo (host `innerHTML` snapshots with path-based selections). The engine calls it with `Page::call`; JS reaches the selection with the `selGet`/`selSet` natives (UTF-16 offsets in JS, chars in Rust). Selection survives focus leaving the host (toolbar buttons) and is dropped when plain content is pressed; a canceled `mousedown` keeps focus. Detached nodes keep their ids in the arena, so find nodes with `descendants(ROOT)` or JS, not `doc.find`, after an undo.
- Editor images: `Page::selected_image` (the edit selection covers exactly one `<img>` child), `begin_image_interaction` (in `begin_edit_selection`: a press on a handle starts an `ImageDrag`, a press on an image selects it), `image_drag_to` (corners keep proportions unless Shift; calls `__imageSet` in `edit.js`, which writes the `width`/`height` attributes; `__imageStart`/`__imageEnd` do the undo checkpoint and `input` event), handles from `nile_layout::handles_of` (shared by hit testing and the renderer's `Overlay::selected_image`), cursors `ResizeNwse`/`ResizeNesw`. `build_image` only uses the picture's aspect ratio when a dimension is missing (two explicit ones used to be forced square).
- Table commands (`edit.js`, `gridOf` builds the cell grid with spans): `tableInsertRow*`, `tableInsertColumn*`, `tableDelete*`, `tableMergeCells`, `tableSplitCell` through `execCommand`; `td.colSpan`/`rowSpan`/`cellIndex` exist in `prelude.js`.
- Tables in the editor (`edit.js`): `insertTable`, `tabInTable`, `deleteAcrossCells`; `closestBlock` returns a `td`, so Enter (`splitBlock`) and Backspace/Delete (`backspace`) treat cells as walls. `Page::default_key` offers Tab to the host first.
- Rich clipboard: `Clipboard::{html, set_html}` (arboard on the system clipboard); the editor's copy asks `__selectionHtml` (via `Range.cloneContents`), paste sends HTML through `__editPasteHtml` -> `pastedBlocks` (the sanitiser: `PASTE_TAGS`, `PASTE_STYLES`, `SAFE_URL`) -> `pasteBlocks`, which splits the current block for multi-paragraph pastes. `call()` returns JSON, so strings need `unjson_string`.
- IME: `Page::{ime_wanted, ime_cursor_rect, ime_preedit, ime_commit, ime_cancel}`. In text inputs the composition is `View::preedit` (layout splices it into the displayed text in place of the selection via `LayoutOptions::preedit`, `Overlay::preedit` underlines it, the real value changes only on commit through `insert_text`); in contenteditable hosts it is an underlined `data-nile-ime` span managed by `__imePreedit`/`__imeCommit` in `edit.js` (not in undo history). Focus changes cancel it. winit's `Ime` events and `set_ime_allowed`/`set_ime_cursor_area` are in `App::sync_ime`.
- Pickers and validation (`web.js`): the engine opens a picker with `Page::open_picker` -> `__pickerOpen(id)` when `picker_opener_at_pointer` says the click hit the glyph (right 28 px; colours: left 30 px, the swatch) or on Alt+Down (`has_picker`); the picker is a plain `.nile-picker` element (UA CSS `.nile-picker`, `.np-*`) shown with `input.popup()` and removed on close; presses inside keep the input's focus (canceled `mousedown`). `Appearance::{Calendar, Clock}` paint the glyphs. Validation is JS (`computeValidity`): flags `valid`/`invalid` (state flags, `:valid`/`:invalid`) are refreshed on `input`/`change` events, a `MutationObserver` over the relevant attributes, and at DOMContentLoaded. A script assigning `value` calls `N.valueSynced` so `View::value_at_focus` (moved from `Page` to `View`) doesn't make blur fire `change`. `Page::drop_files` (shell: `WindowEvent::DroppedFile`, batched until `about_to_wait`) -> `choose_files` or `__fileDrop`. A `<legend>` gets `LayoutBox::border_gap` on its fieldset (`open_legend_gaps`), clipped out of the border by `paint_box`; the UA gives `legend` a negative top margin.
- Drag and drop: `Page::dnd_candidate` (set in `press_here` when `mousedown` isn't canceled and an ancestor has `draggable="true"`) becomes `Page::dnd: Option<Dnd>` after 4 px (`dnd_start` calls `__dndStart`); while it is set `pointer_moved_here` only runs `dnd_move` (hit test -> `__dndMove(overId, x, y)` -> `{accept, effect}`; hover/:hover are frozen), release is `dnd_end(true)` (a `drop` only if the last `dragover` was accepted), Escape in `Page::key` cancels, `cursor()` shows Move/NotAllowed, and `paint_inner` paints the source subtree (`Overlay::only`) translated by the pointer under a 0.65 alpha layer. The events and `DataTransfer` are in web.js (`__dndStart/Move/End`, `__fileDrop` for OS drops, which now also fires `dragenter`/`dragover`). In-page only: no dragging out of the window.
