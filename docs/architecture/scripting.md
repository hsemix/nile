# Scripting runtime and libraries

[Architecture index](README.md)

Implementation notes for people changing Nile: The JS platform in `nile-script`, `@nile/*` libraries, modules, components, crypto, printing, mail, serial, hotkeys and similar. Each note says where the code is and which trap it avoids. They are kept as written while the code was built, so check a name against the source before relying on it.

- Sciter helpers in `prelude.js` follow docs.sciter.com (verified Oct 2026):
  `on()` handlers get `(evt, matched)` with `this` = the attached element; JSX
  returns vnode arrays that `append`/`content`/`patch` render. Check the docs
  before adding more, don't write Sciter API shapes from memory.
- Web platform JS (`nile-script/src/web.js`, spliced at `/*@WEB@*/` inside its own `{}` block so its helper names stay out of the prelude's scope): `URL`, `MutationObserver` (wraps the `N.append/remove/setAttr/...` natives), storage (`localStorage` saved by a 50ms-debounced `N.storageSave` to `ScriptHost::set_storage_file`, flushed on drop; `net::default_storage_file` picks the default), `matchMedia`, `location`/`history`/`navigator`, `ResizeObserver`/`IntersectionObserver` (the engine calls `__observeCheck` from `Page::sync` only while `ScriptHost::observing()`), `fetch`/XHR. Requests go through the `Fetcher` trait (`nile-script/src/net.rs`; `LocalFetcher` by default, `PageFetcher` in nile-engine adds http via `ureq` behind the `net` feature), one worker thread each; `ScriptHost::tick` hands finished ones to `__fetchDone` and asks to be ticked every 16ms while any are pending. `EventTarget.dispatchEvent` already calls `on<type>` properties, don't call them yourself.
- `@nile/ui` (nile-script/src/ui/*.js, embedded with `include_str!` and served by `FileLoader` for `@nile/ui` and `@nile/ui/<name>`, which `resolve` passes through): the optional component library, plain JS over custom elements/SVG, no engine support; each module registers its elements when imported (`define()`) and adds its UA-ish CSS as a `:where()` `<style data-nile-ui>`. `barcode.js` has Code 128/39, EAN-13/8, UPC-A and QR (byte mode, v1-40) and was verified against qrcode/python-barcode/OpenCV with throwaway scripts (not in the repo); the engine test `the_ui_barcode_module_draws_codes_that_match_reference_encoders` holds golden vectors. Add new components there, one file each (register it in `UI_MODULES` in nile-script/src/lib.rs and `ui/index.js`), rather than in the Rust core. Modules: `base` (style/emit/focusable helpers), `barcode`, `drawer`, `splitter`, `grid` (virtual rows, `_paint`/`_mark`, natural-order sort keys computed once). Gotchas when writing components: elements are DOM wrappers, so private fields/methods must not collide with theirs (`_id` is the node id, `_key` the JSX key: use other names); `classList.toggle` doesn't exist (use add/remove); `localeCompare` ignores `numeric`; `:scope >` selectors don't work from the document; a custom element's `connectedCallback` runs asynchronously after the first module script, so setters must work before the DOM is built (the grid keeps state in `_st`). Mouse events carry `shiftKey/ctrlKey/altKey/metaKey` (`UiEvent::Mouse::mods`, from `Page::mods`). More modules: `dialog` (`<nile-dialog>`, `confirm/prompt/alert/dialog`; a `modal.depth` counter in `base` keeps `shortcuts` quiet while one is open), `toast`, `shortcuts` (platform from `@env`'s `PLATFORM`: `navigator.platform` is empty), `tabs`, `accordion`, `combobox` (the last choice stays until the text is committed; async `source` ignores stale answers by a sequence number), `ribbon` (`ribbon(config)`; menus live *inside* the element so its CSS variables reach them), `tiles`, `chart` (SVG strings, hover maths from `_geo`). More gotchas: there is no `focusin`/`focusout` (listen for `blur` on the input itself); element ids are not globals (`window.x = document.getElementById(...)` in tests); in engine tests `Page::run_timers` only fires timers that are due, so a promise that settles via `setTimeout` needs a second wait; the CLI's `--wait` runs before input and `--settle` after it. Later modules: `tree` (items get non-enumerable `_parent`/`_depth`; ids default to the path; rebuilds all visible rows on each change), `keypad` (buttons cancel `mousedown` so the target keeps focus; `fresh` = next digit replaces), `date` (dates are ISO strings, never `Date` objects in state; `formatDate`/`parseDate` tokens; `<nile-date*>` pop up a `position: fixed` calendar like the combobox list), `menu` and `palette` (one open at a time, both bump `modal.depth` and listen on the document in the capture phase; `palette.bind` registers an `always` shortcut; `shortcuts.list()` now includes `run`), `wizard` (validators may return Promises: navigation methods are async). Author CSS in these modules uses `:where(tag) .class` (not a bare `:where(.class)`), because a zero-specificity rule loses to the UA sheet's button/input styles. `@nile/mail` (`ui/mail.js`: a lock-step SMTP client over `@sys` `TCP` (`tls(host)` also upgrades an already-plain socket, which is how STARTTLS works), MIME built by `buildMessage`; the engine test runs a scripted `TcpListener` SMTP server, TLS itself is untested). `@nile/keychain` (`ui/keychain.js` over `keychain.rs`: the `keyring` v4 crate's v1 facade, which picks the native store per target; reached through `__keychain` -> `sysAsync("keychain:<op>")` so it runs on a worker; answers are `N`/`V<text>`/`B<base64>`; cargo feature `keychain`, default in nile-engine; the real-store round trip is `#[ignore]`d: `cargo test -p nile-script --features keychain keychain -- --ignored`, and the engine test must never write a real item). `Intl` (`nile-script/src/intl.js`, spliced at `/*@INTL@*/` after crypto): JS over a locale table (`LOCALES` by language, `REGIONS` overriding), not ICU; numbers are rounded as decimal *strings* (`decimal`/`roundAt`) so 1.005 gives 1.01, currencies use `SYMBOLS`/`NARROW`/`DIGITS` and per-region `cur` maps, dates are CLDR-style patterns (`dateStyles`) or `componentDate`; the engine test `intl_formats_numbers_currencies_dates_and_collates_like_icu` holds the expected ICU strings (U+202F before AM/PM and in French groups, U+00A0 between a letter symbol and the number); `navigator.language` is replaced there from the OS (`call("language")`/`country`). `@env` `reveal`/`moveToTrash`/`openWith` live in `nile-script/src/desktop.rs` (macOS moves into `~/.Trash`, Windows PowerShell + VisualBasic FileSystem, Linux `gio`/`trash-put`/XDG fallback with a tested `trash_into_xdg`). Crypto: `nile-script/src/crypto.rs` (`call(op, args)` over `ring`: random, digest, hmac, hmac_verify, pbkdf2, aes_gcm_seal/open; bytes as base64) is reached by the sync `cryptoCall` native (random only) and, for everything heavy, by `sysAsync("crypto:<op>")`, which `sys::start` routes to the worker thread; `crypto.js` is the Web Crypto shim (spliced at `/*@CRYPTO@*/`, raw keys held in a WeakMap, errors named like DOMExceptions) and `ui/passwords.js` is `@nile/crypto`. Printing (`ui/print.js`, `ui/escpos.js`, registered in `UI_MODULES` as `@nile/print` and `@nile/escpos`, resolved like `@nile/ui`): plain JS over `@sys` (`spawn` for `lpstat`/`lp`/PowerShell, `TCP` for port 9100); the Windows paths (`Get-CimInstance`, `Start-Process -Verb PrintTo`, the winspool P/Invoke script written to the temp folder) are unrun here, CI doesn't print either. `Window.this.print`/`exportPdf` go `N.printRequest` -> `View::print_requests` -> `Page::run_print_job` (paged.rs: `write_pdf`, then restores the viewport/scale) -> `__printReady` in web.js, which imports `@nile/print` for the print case. Engine tests fake `lp`/`lpstat` with shell scripts on `PATH` (unix only) and a loopback `TcpListener`. `View::sync` clears the focus when the focused element left the document (a removed popup used to swallow every key).
- `@nile` / `@env` modules (`@sciter` resolves to `@nile`, kept for Sciter apps): the resolver passes the names through and `FileLoader` declares tiny wrapper modules over `__sciterModule` / `__envModule` (defined at the end of `web.js`; OS access is the single `envCall` native in `envmod.rs`). Shapes follow docs.sciter.com/docs/JS.runtime (module-sciter, module-env).
- Blob, FormData, streams, WebSocket (`web.js`): `Blob` keeps a `Uint8Array` (`_data()`; `File extends Blob`, a path-backed one for `<input type=file>` reads through `fsCall`); `FormData` collects a `<form>`'s fields and `encodeMultipart`/`decodeMultipart` do `multipart/form-data` for `Request` bodies and `Response.formData()`; `ReadableStream` is a queue plus waiting readers with `pull`/`start`, `WritableStream`/`TransformStream`/`TextEncoderStream`/`TextDecoderStream` are thin chains. `WebSocket` is RFC 6455 written in JS over `@sys`'s `TCP` (handshake, masked frames, fragments, ping/pong, close handshake with a 3 s timeout); `wss://` calls `TCP.tls(host)` (sys.rs op `tls`: rustls with the webpki roots, behind nile-script's `tls` feature which nile-engine's `net` enables; a TLS read polls with a 30 ms timeout so writes can interleave). The server's `Sec-WebSocket-Accept` isn't validated. An idle socket keeps a read pending, so `ScriptHost::tick` polls every 30 ms while only sys work is pending (fetches: 16 ms).
- Class components (`prelude.js`, "class components" section): `expand` turns a JSX tag whose function extends `Element` into a `comp` item; `instantiate` makes a `<div>`, sets `adopting` so `Node`'s constructor takes that element id (class fields and `constructor` run), then `this(props, kids)`, `draw` (the `render()` root's attrs over the props' + its children go onto the element) and a queue (`mountQueue`, flushed by `mounted()` from `appendChild`/`insertBefore`) for `componentDidMount`; `patchChildren` reuses an element by `instanceof` + key and calls `refresh`; `unmounting` (from `removeChild`/`remove`/`content`) calls `componentWillUnmount`; `componentUpdate` batches into a microtask. `Element.value` of `<form>`/`behavior="form"` is an object (`formValue`). `@debug` (`debugModule`: handler hooks read by `report`/`console`) and `@storage` (`storageOpen`: JSON file via `fsRun`) are in `web.js`, registered in `FileLoader` like `@sys`.
- `@sys` pipes/TTY/watch: `Res::Pipe` (a `UnixListener`/`UnixStream`; the socket file is removed on close, a stale one is reused) on Unix, `Res::Tcp` on the loopback with the port in `nile-pipe-<name>.port` elsewhere (written without a Windows compiler: CI checks it); `Res::Tty(fd)` reads stdin / writes stdout or stderr, size and mode come from `stty`; `fs.watch` is JS (`web.js` `watchFs`): with cargo feature `watch` (default in nile-engine) `sys.rs` `watch_new`/`watch_next` wrap the `notify` crate (events batched 40 ms, paths mapped back to the spelling given, flags merged), else or if the system refuses it a 250 ms `setInterval` over `snapshot`s of `stat`/`readdir`.
- `prototype:` (web.js `__applyPrototypes`): `ComputedStyle::prototype` (class name and file, read from the declaration's raw text because values are lower-cased; `StyleMap::{has_prototypes, prototypes}`); `Page::apply_prototypes` (in `sync`, once per document version, only when some element has one) passes `[id, class, url]` to JS, which imports the file (`__DIR__ + url`), finds the class (`protoClass`: named export, a class of that name, the default export, or a global/`eval`-visible class) and `protoBind`s each element: a throwaway `new Cls()` with `adopting` set runs fields (copied onto the element's existing wrapper), `Object.setPrototypeOf`, `"on ..."` methods are subscribed (`handlerMethods`), `componentDidMount`, `liveComps` so removal calls `componentWillUnmount`. A restyle that drops the prototype doesn't unbind. Element-scoped queries (`Query::matches_in_scope`, native `matchesIn`): a leading combinator parses with `ParseRelative::ForScope` (which puts `:scope` in front; don't use it for ordinary selectors, it prefixes them all), and `:root` is rewritten to `:scope` (the crate's `:root` didn't match under a scope element). `:tab-focus` is the `tabfocus` state flag set by `focus_next` through `Page::tab_focus_next`; `:owns-focus` is computed.
- `customElements` (web.js, after `__applyPrototypes`): `define` records `{Cls, ext, attrs}`, binds matching elements with `protoBind`, and `customTags` (prelude) makes `new Cls()` create the right tag. A MutationObserver on the document drives `connectedCallback`/`disconnectedCallback` (`_ce`/`_ceOn` flags); `attributeChangedCallback` comes from patched `setAttribute`/`removeAttribute` (so detached elements report). `createElement` is wrapped to upgrade synchronously; `attachShadow()` returns the element (no shadow DOM, slots).
