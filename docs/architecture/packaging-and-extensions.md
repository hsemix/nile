# Packaging, updates, lifecycle and native extensions

[Architecture index](README.md)

Implementation notes for people changing Nile: `--pack`, signed updates, single-instance and file/URL events, and the native extension host. Each note says where the code is and which trap it avoids. They are kept as written while the code was built, so check a name against the source before relying on it.

- Native extensions (`docs/extensions.md` is the contract): `nile-extension-sdk` is the C ABI (u64 tokens, never pointers; size/version fields; borrowed slices valid only during the callback; `guard` catches panics, so extensions must build with `panic = "unwind"`: the workspace `extension` profile does, while the engine's `release` profile stays `panic = "abort"` because unwinding costs ~1.2 MB of binary). `nile-extensions` (`Extensions`, one per `ScriptHost`) holds a `Loaded` per package: `Shared` state behind a mutex (`accepting`, `calls`, `subscriptions`, bounded `done`/`events` queues, resources), found by the host token through a `Weak` registry so a late `complete` after teardown gets `NILE_CLOSED`. `start` dispatches without any lock held; acceptance of a reply is atomic under the state lock and then wakes the loop (`set_waker`, the shell sends `UserEvent::ExtensionWake`). A reply over `MAX_BYTES` (1 MiB) ends the call with `RESULT_LIMIT`. `Loaded::drop` is the shutdown sequence (stop accepting, `context_dispose`, resource drops, `shutdown`, then unload; a failed teardown or a failed init that left `user` state `quarantine`s = keeps the library mapped; after a failed `nile_extension_init` no hook runs, after a failed `context_init` only `shutdown`). `ScriptHost::configure_extensions`/`discover_extensions` (nile-script/src/extensions.rs) take the nearest `nile.json` (the search stops before the root and the home folder), call `nile_extension_pack::prepare` (validates manifests, materializes native files for packed apps into the cache, returns absolute library paths and the data path) and then `Extensions::load_prepared`; wrapper modules import `@native` (resolved only under a package root) which exports `__nileExtensionScope(host)` from `extensions.js` (Promises keyed by host:call, subscriptions, `__nativeExtDeliver` called from `tick_extensions`). `Extensions::load` is the older direct loader used by tests. Pack cache (`nile-extension-pack`): `os_root` + `resolve_root` (links in the OS root are followed, any link below it is refused by `directory`), `materialize` (per-hash file lock, staging dir, verify, atomic rename into an immutable `object-*` generation, never rewritten). The SQLite package owns an ordered worker per context and interrupts running statements through a progress handler on cancel/shutdown.
- Packaging (`nile-dom/src/vfs.rs`): `nile --pack folder -o app` writes the running `nile` binary + deflated files + a text index + trailer (`index_len`, `data_start`, `NILEPAK1`); `vfs::mount_self()` (first thing in `main`) finds it and mounts it at `vfs::MOUNT` (`/__nile_app__`, `C:\__nile_app__`), a path no disk has. All file reads for pages go through `vfs::{read, read_to_string, exists, canonicalize}` (page, includes, scripts/modules, images, fetch, frames, content-style), which serve the mount from the archive; `this://app/x` URLs map to it (`url_to_path`/`app_url`, used for `location`, `fetch`, frame `src`). Storage files of packed apps are keyed by the executable's name. Start file: `vfs::start_file` (run order of Sciter's scapp: scapp/main/index .htm[l]); `nile` with no file looks in the pack, the program's folder, then the cwd; a folder argument opens its start file. macOS re-signs the packed copy ad hoc (`codesign`), which Apple silicon needs. Bootstrap mode: a `.js` start file (`run.js` is first in `start_file`'s order) makes `main` build a hidden-window page (`window-state="hidden"`) with `<script type="module" src="run.js">`; `application` (web.js: `start`, `run` = 0, `quit` -> `WindowCommand::Quit` -> `Action::Quit`), `__DIR__`/`__FILE__` (`with_location` in nile-script: declared on the module's first line; page-wide getters from `location` for classic scripts) and `@sys` (`__sysModule` over the `fsCall` native, `envmod::fs`: stat, readdir, read, write, unlink, mkdir, rmdir, rename, copyfile, realpath; the rest in `nile-script/src/sys.rs`: one process-wide resource table (files, processes, pipes, TCP/UDP) behind the `sysCall` native, blocking reads/accepts/waits on worker threads via `sysStart` -> `SysState::take_done` -> `__sysDone`, ticked like fetches; virtual paths readable, `vfs::list_dir`); `App::bootstrap` ends the program when only the hidden host window is left. Executable icons (`nile-shell/src/bundle.rs`): `--pack ... --icon` makes a macOS `.app` (plain signed program + `Contents/Resources/app.nilepack` read by `vfs::mount_self`'s second lookup, since an archive appended to a signed Mach-O fails strict `codesign` validation; `sips`/`iconutil` for the `.icns`) and, on Windows, writes RT_ICON/RT_GROUP_ICON into the runtime with `UpdateResourceW` before appending (uncompiled here: CI). `--version/--company/--description/--copyright/--name` (`bundle::AppInfo`) write the Windows `RT_VERSION` resource (`version_resource`, byte layout unit-tested) and the `Info.plist` keys; on Linux `--pack` with an icon or `--category` writes `<out>.desktop` (+ `.png`) (`desktop_entry`, `--install` copies it to `~/.local/share/applications`) and `App::create` sets the application id to the executable's name (winit's Wayland/X11 `with_name`, written without a Linux compiler to hand). A `.png` icon is also embedded in the archive as `__nile_icon.png` and used as the window icon of a packed program. Not done: an unpack command.
- Updates: `nile-shell/src/updates.rs`. An update is a signed replacement of the app's *archive* (`.nilepack`, an archive with no runtime), not the executable. `Config` comes from the app's `nile.json` (`id`, `version`, `update.publicKey`/`url`); `stage` checks minRuntime, SHA-256 (ring), the Ed25519 signature over `nile-update-v1\n<version>\n<sha256>\n`, that it is newer and that it opens as an archive, then writes `<user data>/nile/updates/<id>/current.nilepack` + `current.json`; `staged` re-verifies it at start-up and `vfs::mount_self_with(updates::replacement)` mounts it instead of the program's own archive (the new `nile.json` may carry a rotated key). JS (`application.checkForUpdates/downloadUpdate/restartForUpdate/version/updateReady` in web.js) uses `fetch` and the host functions `nileUpdateConfig/Newer/Stage/Restart` registered with `add_default_host_fn`; a restart spawns the program with `NILE_RELAUNCH=1`, which waits for the old single-instance endpoint to go (`instance::is_running`). `nile --keygen`/`--release` are `keygen_command`/`release_command`. Tests keep the store in a temp dir (`TEST_STORE`).
- App lifecycle: `nile-shell/src/instance.rs` (`acquire(id, payload, on_message)` -> `Role::{Primary(Guard), Secondary}`: a Unix socket in `$XDG_RUNTIME_DIR`/temp or, on Windows, a loopback port file; the second launch sends one JSON line and waits for `ok`); `run()` builds the event loop first, checks `single_instance_id(file)` (the `<html app-single-instance>` tag scanned as text, or `nile.json`) before the page's scripts run, and passes `UserEvent::Application(json)` (`type`: `second-instance` | `open-url` | `open-file`) to `App::application_event`, which raises the first non-host window and calls `Page::application_event` -> `__applicationEvent` (web.js, fires on `document` and `window`). Plain CLI arguments after the page, after `--`, or all of them in a packed app are `nile_script::app_arguments()` (`application.arguments`, `@env` `arguments()`). `openevents.rs` (macOS): Apple event handlers for `GURL` and `odoc` through `NSAppleEventManager` (re-installed in `resumed` because AppKit takes `odoc` at finishLaunching) plus `application:openURLs:` added to winit's delegate class with `class_addMethod` for documents that launch the app. `@media` (extensions/media, a native extension, not core: `nokhwa` camera on its own thread, `cpal` microphone on its own thread because the streams are !Send, `jpeg-encoder` for photos; subscriptions `media.camera.start`/`media.microphone.start` acknowledge with a stream id (the call id) then emit events with one buffer: RGBA preview scaled under 1 MiB, or i16 PCM; `camera.photo` uses the newest full frame kept in a shared slot; microphone audio waits for room, camera frames are dropped; `wrapper media/package/index.js` turns buffers into `ImageData`/WAV; `nile --pack --camera/--microphone` write the Info.plist usage strings; unexercised on real hardware). `@nile/serial` (`ui/serial.js` over `serial.rs`: the `serialport` crate with default features off so Linux needs no libudev; reached through `__serial` -> `sysAsync("serial:<op>")` on worker threads; each open port has a writer handle and a cloned reader handle, the reader polls at 50 ms and ends when the port leaves the table, so `close` unblocks it; the JS side keeps one read pending and buffers up to 1 MiB for `read`/`readUntil`; the engine test is Linux-only because macOS refuses to open a pty slave by name; cargo feature `serial`, default in nile-engine; the camera/microphone idea is to be an extension, serial is not). Screens: `View::screens` (`nile_script::ScreenInfo`, filled by the shell's `screens_of` in `sync_window`, which also calls `Page::screen_changed` -> `resolutionchange`) -> native `screensInfo` -> `Window.screens/screenBox/screen` (web.js). Machine state: `desktop.rs` `query` (`online`: UDP connect to a public address; `power`: pmset/PowerShell/sysfs; `idle`: ioreg/PowerShell/xprintidle) via `sysAsync("desktop:<op>")`, exported from `@env` (add new `@env` names to the wrapper in `FileLoader` too); `navigator.onLine` polls every 5 s once an `online`/`offline` listener exists. Global hotkeys: `application.registerHotkey` (web.js) keeps ids in a Map and pushes `[[id, accel]]` through `N.hotkeysSet` -> `Environment::set_hotkeys` -> `View::hotkeys`; the shell's `hotkeys.rs` (`global-hotkey`; `translate` respells accelerators, `asked` stops a refused key being retried every sync) registers them for the owning window from `App::sync_hotkeys`, reports `ok`/`refused` and presses back through `Page::hotkey_event` -> `__hotkeyEvent`. `nile-script/src/integration.rs`: `registerProtocol`/`registerFileType`/`loginItem` per platform (`reg.exe`, `.desktop` + `xdg-mime`, LaunchAgent); `bundle.rs` writes `CFBundleURLTypes`/`CFBundleDocumentTypes` and the `.desktop` `MimeType`.
