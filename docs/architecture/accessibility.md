# Accessibility

[Architecture index](README.md)

Implementation notes for people changing Nile: The accessibility tree, text runs and live regions. Each note says where the code is and which trap it avoids. They are kept as written while the code was built, so check a name against the source before relying on it.

- Accessibility: `nile-engine/src/a11y.rs` builds an `A11yTree` (plain structs: role, name, value, bounds in window logical px, flags, children) from the DOM, styles and layout (`Page::a11y_tree`; implicit roles from tags and `<input type>`, `role` overrides, names from `aria-*`, `<label>`, `alt`, legends, own text; hidden/empty wrappers dropped; frames graft their tree below the frame node, ids carrying the frame element in the high 32 bits) and carries requests back with `Page::a11y_action` (`Click` = click event + `click_default`, `Focus`, `SetValue`, `Increment`/`Decrement`, `ScrollIntoView`). `A11yTree::to_json` + `nile_view_accessibility_tree`/`_action` serve C hosts. The shell (`nile-shell/src/access.rs`, `app.rs`) creates each window invisible, makes an `accesskit_winit::Adapter` (it must see the window before it is shown), converts the tree to a `TreeUpdate`, answers `InitialTreeRequested`/`ActionRequested` through the event loop (`UserEvent`), and re-sends when `Win::sync_access`'s stamp (doc version, focus, scroll, size, frame versions) changes; `update_if_active` means nothing is built unless assistive technology is on. Tests: the engine test checks roles/names/states/actions, the shell test feeds the update to `accesskit_consumer`. No real screen reader has been run against it: macOS refuses `System Events` UI scripting without permission, so check with VoiceOver by hand.
- Text in accessibility: `StaticText` nodes become AccessKit `TextRun`s (`access.rs::text_run`: character lengths, word starts); text inputs/textareas get one child run per line of the value (`input_runs`, ids with `RUN_BIT`, mapped back by `owner_of` in `a11y_action`), and `A11yNode::selection` (`A11ySelection` of `(run id, char)`) is set on the focused input (from `View::{anchor, caret}`) and on the focused `contenteditable` host (from `View::edit_sel`, DOM offsets mapped to collapsed text).
- Live regions: `A11yNode::{live, live_atomic}` from `aria-live`/`aria-atomic` and the `alert` (assertive), `status`, `log` (polite) roles (`is_live_region` keeps even empty ones from being dropped as wrappers); the shell sets AccessKit's `live`/`live_atomic`, and AccessKit raises the platform event when text inside changes (ids are stable, so a changed text node is a change).
