# Virtual data grid

```sh
cargo run -p nile-shell -- examples/virtual-grid/index.html
```

This example virtualizes **both rows and columns** using HTML, CSS and JavaScript.
It represents 100,000 × 100 cells, switchable to 1,000,000 × 100. The dataset is
synthetic: values are generated by `valueAt(row, column)` on demand, rather than
allocating millions of records. This demonstrates rendering large logical grids,
not the cost of loading, sorting or storing a real dataset.

Scroll in either direction, jump to a row, or use First/Last. Arrow keys,
Page Up/Down and Home/End navigate; Ctrl/Cmd+Home/End reaches the data boundaries.
Enter or F2 opens an editor; Enter saves and Escape cancels. Edits are kept in
an in-memory sparse map, and remain when their cells leave the viewport. Reload
resets them. The inspector reports the mounted cell count and rendered ranges.

## How it works

The implementation is in [app.js](app.js).

1. `#viewport` is a constrained scrolling element. `#spacer` has the full logical
   dimensions: `rowCount * 36` pixels tall and `100 * 140` pixels wide.
2. `bounds()` calculates the visible indices from `scrollTop`, `scrollLeft`,
   `clientHeight` and `clientWidth`. Three rows and two columns of overscan extend
   each edge. End indices are exclusive and clamped to the dataset.
3. `render()` creates only that rectangular slice. `#cells` is positioned at
   `firstRow * 36`, `firstColumn * 140`; its grid tracks are fixed-width columns.
   The separate column header follows horizontal scrolling.
4. `schedule()` coalesces scroll and resize notifications into one
   `requestAnimationFrame` callback. If the rendered bounds haven't changed,
   scrolling updates header alignment without rebuilding the cells.
5. Selection and edits use logical indices, independent of DOM elements.
   `reveal()` scrolls a keyboard-selected cell into view. `valueAt()` consults the
   edit map before generating a value.

At 1280 × 820, roughly 190 cells are mounted initially; the count varies with
viewport size, scroll position and overscan. It does not grow with row count.

## Using real data

Replace `valueAt()` with lookup into your data model or cache. Load missing data
in pages and schedule a forced render when a page arrives. Use stable record IDs
for edits if records can be reordered. Sorting and filtering belong in the data
model, not the mounted DOM; expensive operations may require host-side processing.

Fixed row heights and column widths are intentional. Variable dimensions require
prefix sums or another index of cumulative offsets. This example rebuilds a
small slice when bounds change; pooling cells is a possible further optimization.
It does not add engine features or require an engine patch.
