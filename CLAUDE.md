# Nile

An open-source, embeddable HTML/CSS/JS UI engine in Rust, in the spirit of
Sciter: its own renderer, **no webview**, small enough to ship inside desktop
apps. The motivation is to give Sciter's well-designed approach an open-source
home that doesn't depend on one person. Read `README.md` for the supported
CSS, known gaps and roadmap.

## Goals that shape decisions

- **Own rendering pipeline.** Never fall back to a system webview or Chromium.
- **Sciter compatibility where sensible.** When designing JS/DOM APIs and CSS
  extensions, follow Sciter's shapes so existing Sciter apps can port.
  Prefer web standards where Sciter matches them.
- **Cross-platform.** Development happens on macOS; Windows and Linux must keep
  working. CI runs on all three. No platform-specific code outside the shell
  (and later, GPU backends) without a `cfg` fallback.
- **Small and embeddable.** Watch binary size and dependency weight. Prefer
  focused crates over large frameworks. Will expose a C ABI later.
- **Rust only** for the engine.

## Layout

```
crates/
  nile-dom     arena DOM (NodeId into Vec<Node>), html5ever parsing
  nile-style   CSS parsing (cssparser), cascade, inheritance, UA stylesheet
  nile-text    Parley wrapper: shaping, line breaking, font fallback
  nile-layout  styled DOM -> Taffy tree, text measurement, flattened boxes
  nile-render  paints LayoutTree onto a Skia canvas
  nile-script  QuickJS via rquickjs; native DOM bridge + prelude.js (web DOM classes)
  nile-engine  `Page`/`View`: input, forms, scrolling, window config, painting into a buffer (no windowing dep)
  nile-shell   `nile` binary: winit + softbuffer window around nile-engine, headless --png mode
  nile-capi    `libnile` C ABI (cdylib + staticlib); `include/nile.h` is generated by build.rs (cbindgen)
examples/      test pages
docs/          README screenshot
```

Data flows one way: dom -> style -> layout (uses text) -> render. Keep crate
dependencies in that direction. `nile-render` must not depend on `nile-dom`.

## Commands

```sh
cargo run -p nile-shell -- examples/hello.html                 # window; R reloads, wheel scrolls
cargo run -p nile-shell -- examples/hello.html --png out.png --scale 2
cargo run -p nile-shell -- examples/interact.html --png out.png --hover 40,40   # or --press / --click X,Y
cargo run -p nile-shell -- examples/scripting.html --png out.png --click 60,80 --wait 400
cargo run -p nile-shell -- examples/animations.html --png out.png --hover 60,50 --settle 150   # --settle: wait after input (transitions)
cargo run -p nile-shell -- examples/measure.html --png out.png
cargo run -p nile-shell -- examples/todo/index.html --png out.png --click 60,128   # modules + JSX
cargo run -p nile-shell -- examples/forms.html --png out.png --click 60,66 --type "Ada{Backspace}x"
cargo run -p nile-shell -- examples/scrolling.html --png out.png --wheel 100,100,-60
cargo run -p nile-shell -- examples/forms.html --png out.png --click 60,66 --type "Ada{Home}{Shift+End}{Cmd+c}"
cargo test --workspace
NILE_STORAGE_DIR=off cargo test --release -p nile-engine bench_scroll -- --ignored --nocapture   # scroll/hover frame times on the Word page
cargo clippy --workspace --all-targets -- -D warnings          # CI enforces this
```

## Performance

`[profile.dev]` in the root `Cargo.toml` optimises dependencies fully and our crates lightly: an
unoptimised debug build made a wheel tick on the Word example cost ~16 ms (40 ms spikes); now it is
~1-4 ms, in line with release. Keep it when touching profiles. Scrolling doesn't re-cascade `:hover` per wheel tick: `Page::hover_after_scroll` defers it 90 ms (settled by `tick`, a press or a pointer move). `NILE_TRACE=1` prints style, layout,
paint and animation timings; `bench_scroll` (ignored test) replays wheel events with the pointer resting on the page.

## Working conventions

- **Check visual changes by rendering.** After any layout, style, text or paint
  change, render the relevant example with `--png` and look at the image.
  Tests passing isn't enough for visual work.
- **Add an example page** in `examples/` for each new feature (e.g.
  `examples/inline.html`) so it can be checked visually.
- **Unit tests** go next to the code (`#[cfg(test)]`). Layout tests assert box
  rects. Use `margin: 0` on body to keep numbers simple.
- **Unsupported CSS is ignored silently**, like a browser. Never panic on bad input.
- Mark known shortcuts with `TODO:` and say what the real fix is.
- Update the README's "supported" and "known gaps" sections when they change.
- Pin dependency versions in the root `Cargo.toml` `[workspace.dependencies]`;
  crates use `.workspace = true`. Commit `Cargo.lock`.

## Gotchas

- The document is `Rc<RefCell<Document>>`, shared by the shell and the script
  host. Never hold a borrow across a call into scripts (`ScriptHost::dispatch`,
  `tick`, `run`): they borrow it mutably. Scripts bump `Document::version`; the
  shell's `Page::sync` restyles when it changed. Detached nodes stay in the arena.
- Scripts read layout through `nile_script::Environment`, implemented by the
  shell's `Env` over the shared `View` (styles, layout, viewport, scroll). Each
  query syncs and relays out first, so don't hold a `View` borrow while calling
  into scripts. Native `Option::None` reaches JS as `undefined`, not `null` —
  normalise in `prelude.js`.
- Boxes are `content-box` unless `box-sizing: border-box` (Taffy's own default
  is border-box, so `taffy_style` sets it explicitly).
- Sciter helpers in `prelude.js` follow docs.sciter.com (verified Oct 2026):
  `on()` handlers get `(evt, matched)` with `this` = the attached element; JSX
  returns vnode arrays that `append`/`content`/`patch` render. Check the docs
  before adding more, don't write Sciter API shapes from memory.
- `overflow` boxes: layout gives each clipping element a `ScrollBox` (padding-box
  clip + scrollable extent) and `LayoutBox::subtree_end` marks where its subtree
  ends in the flat paint list. Scroll offsets live in the shell's `View`
  (`scroll_offsets`); `LayoutTree::placements(offsets)` turns them into per-box
  shifts and clips, used by `hit_test_scrolled`, `text_index_at_scrolled` and
  `node_rect_scrolled`, and the renderer applies the same offsets while painting.
  Use the `_scrolled` variants anywhere a pointer or script coordinate is involved.
- Form controls: `Page` in the shell owns default actions (`click_default`:
  checkbox/radio/label) and text editing (`edit_key`, `caret` in chars of `value`).
  An `<input>`'s text is synthesized in layout (`build_control_text`), the
  renderer draws check/radio marks from `appearance` + `checked` and the caret
  from Parley's `Cursor`. `value` is the `value` attribute; `checked`/`disabled`
  are `Document` state flags. The selection (`anchor`, `caret` in chars of `value`)
  lives in the shared `View` so scripts can read/set it; the renderer highlights it
  from `Overlay::selection`. The clipboard is behind the shell's `Clipboard` trait
  (system via `arboard` with default features off; in-memory for headless/tests).
- `<select>`: `<option>`s are `display: none` in the UA sheet; layout draws the
  chosen label as the select's text and, when `LayoutOptions::menu` is set (from
  the shell's `View::menu`), builds a `MenuBox` that the renderer paints last. The
  shell owns open/highlight/choose (`Page::menu_*`, `select_key`, `choose_option`);
  the choice is the option's `selected` state flag. Changing the menu or scrolling
  invalidates the cached layout.
- Page text selection: `View::page_sel` holds two `TextPoint`s (a text run's index in `LayoutTree::boxes` + byte), valid for one `Document::version`. Layout provides `text_point_at`, `word_at`, `selection_ranges`, `selection_text` (control text and padding spacers excluded); the renderer highlights `Overlay::page_selection`. Pressing on non-focusable content starts it in `Page::begin_page_selection`, but only text whose style has `user_select != None` (the default is *none*, as in desktop UIs; opt-in via `user-select`, a `selectable` attribute (UA rule) or `behavior: htmlarea`; verified against sciter.com docs).
- `<optgroup>`: `select_options` returns option *and* optgroup rows in document order, so every row index (menu highlight, list rows, keyboard) counts headings; `option_disabled` makes a heading a disabled row, which stepping and range selection already skip. A list-box press selects at once (`list_click` from `press`, `list_press` stops the click repeating it) and `list_drag` extends it while the button is down.
- List boxes (`<select multiple>` / `size > 1`, `list_rows`): layout gives the select a fixed height of `size` rows and builds a `ListBox` (rows, scroll) per select in `LayoutTree::lists`; the renderer paints it inline after the box. Its scroll offset lives in `View::scroll_offsets` under the select's id (not a `ScrollBox`). The shell's `list_click`/`list_key` set the `selected` state flags. The drop-down `MenuBox` has its own `scroll`/`max_scroll` and flips above the select when `LayoutOptions::scroll_y` + viewport leave more room there.
- Tables (`build_table`): a table is a Taffy grid with auto tracks. Cells get explicit grid lines from `colspan`/`rowspan`; each `<tr>` becomes an empty grid item behind its cells (so row backgrounds paint); `thead` rows go first and `tfoot` last; `border-spacing` is the gap plus padding, and `border-collapse` zeroes the gap and gives cells negative top/left margins so borders overlap. Taffy's `item_is_table` makes the table shrink-wrap. Middle/bottom `vertical-align` wraps the cell's children in an anonymous flex-column node with auto margins (anonymous nodes have no `NodeCtx`, which `flatten` allows).
- Restyle without relayout: `View::restyle`/`animate` compare the old and new `StyleMap` with `StyleMap::same_layout` (a `ComputedStyle` clone with the paint-only fields copied over, then `==`). If only paint properties differ and the DOM didn't change, the `LayoutTree` is kept and `refresh_paint` re-bakes transforms. Text `color` counts as paint-only too (`same_layout_with`): the renderer takes it from `styles` via `TextContent::owners` instead of the shaped brush, except for control text and pages with generated `::before`/`::after` content; inline elements keep background/border changes layout-affecting because those are baked into the text run (`InlineDeco`). `StyleMap::state_deps` says which of `:hover`/`:active`/`:focus` any selector mentions; `Page::set_interaction` skips the restyle when the changed state isn't one of them. When you add a `ComputedStyle` field that layout never reads (and that isn't baked into `LayoutBox`/`TextContent`), add it to `same_layout`; otherwise leave it out. `NILE_TRACE=1` prints style/layout/paint/animate timings (`traced` in the shell); `examples/stress.html` is the 1,500-row benchmark page. `cursor` is inherited and mapped to winit's `CursorIcon` by `App::sync_cursor`.
- Embedding: everything that isn't winit lives in `nile-engine` (`Page` is the entry point, with `pub` fields/methods for the shell and C API; keep winit and arboard out of it, `system-clipboard` is an optional feature). `nile-capi` wraps `Page` in `NileView` with `extern "C"` functions, each guarded by `catch_unwind`; adding one regenerates `include/nile.h` on build (commit it). Scripts get `host.name(...)` (JSON in/out, registered with `ScriptHost::register_host_fn`), the host gets `eval`/`call`. `examples/c/render.c` is the smoke test; build it when you change the API.
- Window: `nile-engine/src/window.rs` parses the root `<html>`'s `window-*` attributes (`WindowConfig`, verified against docs.sciter.com/docs/HTML/html-window) and `role="window-*"` (`role_at`). `App::resumed` builds the winit window from it; scripts and role buttons push `WindowCommand`s (nile-script) onto `View::window_requests`, which `App::sync_window` drains after every event and tick (it also follows `document.title` and publishes `View::window_rect` for `screenX`/`outerWidth`). Frameless windows resize via `edge_at` + `drag_resize_window` and drag via `Page::caption_press` + `drag_window`; both must run inside the mouse-press handler. Headless runs never create a window, so commands just queue.
- `::marker`: parsed as `PseudoElement::Marker`, cascaded per list item into `StyleMap::markers` (`MarkerStyle`: style, optional colour, optional `content`), not into boxes; `build_markers` uses it, and `ListMarker::color` is only set when the rule sets a colour (otherwise the item's live colour is used so paint-only restyles stay correct). `list-style-position: inside` adds `inside_marker_width` to the item's left padding in `taffy_style` and draws the marker at the content edge.
- Lists and form widgets: list markers aren't boxes. `build_markers` (after flatten) makes a `ListMarker` per `display: list-item` element (`LayoutTree::marker`), numbered by `list_numbers` (`start`/`reversed`/`value`); the renderer draws it left of the item (bullets are shapes, counters shaped text). `<summary>` is a list item with a disclosure triangle, toggled in `Page::click_default`. `<progress>`/`<meter>`/range are `appearance: progress|meter|range` painted by `paint_control_mark` from `ComputedStyle::control_fraction`; range input handling is `Page::range_*`; `<input type=number>` is `appearance: spinner` (arrows painted in `paint_control_mark`, stepping in `Page::number_step`, colour/date/time rules in `nile-engine/src/inputs.rs` (`accepts`, `step`, swatch painted from `ComputedStyle::swatch`), file inputs: a click queues `View::file_request`, the embedder answers `Page::choose_files` (paths live in the internal `nile-files` attribute, JS `files` builds `File`s), arrow hit test `number_arrow_at_pointer`). `white-space` is applied per text node in `apply_white_space`. `text-overflow: ellipsis` is handled at paint time (`TextContent::ellipsis`).
- Rich-text editing: `contenteditable` hosts. The *selection* lives in Rust (`View::edit_sel`, two `DomPoint`s: text-node char offset or element child index) so layout can draw and move it; layout maps DOM positions to shaped text through `TextContent::{nodes, marks}` (per text node: char -> run byte, built in `InlineText::collect` by `apply_white_space_mapped`) with `LayoutTree::{text_point_of, dom_point_of, dom_caret_rect, caret_painted, dom_point_at}`. `nile-engine/src/editing.rs` handles what needs layout (pointer placement, Up/Down/Home/End, caret drawing via `Overlay::dom_caret`, scroll-into-view, clipboard keys); everything that edits the DOM is JS in `nile-script/src/edit.js`, spliced into the prelude at `/*@EDIT@*/` (so it shares `N`, `wrap`): `Range`/`Selection`, `execCommand`, typing (`__editKey`, called by `Page::edit_dom_key`), deleting/splitting/merging blocks, inline formatting by wrapping/isolating text nodes (`FORMATS` table), lists, undo (host `innerHTML` snapshots with path-based selections). The engine calls it with `Page::call`; JS reaches the selection with the `selGet`/`selSet` natives (UTF-16 offsets in JS, chars in Rust). Selection survives focus leaving the host (toolbar buttons) and is dropped when plain content is pressed; a canceled `mousedown` keeps focus. Detached nodes keep their ids in the arena, so find nodes with `descendants(ROOT)` or JS, not `doc.find`, after an undo.
- Inline `vertical-align` (`sub`/`super`/length) is a per-run baseline shift: layout sums `baseline_shift` of the open inline elements into `TextStyle::shift` -> `TextBrush::shift`, and the renderer subtracts it from glyph y and the baseline. It doesn't affect line height.
- Animation events: `Animator::update` queues `AnimEvent`s (`transitionend`, `animationstart`, `animationend`); `Page::animate` drains them with `take_events` and emits `UiEvent::Animation` (never drain inside `sync`, `emit` calls it).
- `position: fixed`: layout hands such boxes to an anonymous viewport-sized absolute layer (`FIXED_BLOCKS`), marks `LayoutBox::fixed`, and `placements` cancels the page scroll for the subtree using `LayoutTree::page_scroll` (kept current by `View::layout()`); the renderer resets to the base matrix. `sticky` is in-flow (`Position::Sticky`) with `LayoutBox::sticky_shift(scroll, viewport_h)` used by both `placements` and the renderer.
- Web platform JS (`nile-script/src/web.js`, spliced at `/*@WEB@*/` inside its own `{}` block so its helper names stay out of the prelude's scope): `URL`, `MutationObserver` (wraps the `N.append/remove/setAttr/...` natives), storage (`localStorage` saved by a 50ms-debounced `N.storageSave` to `ScriptHost::set_storage_file`, flushed on drop; `net::default_storage_file` picks the default), `matchMedia`, `location`/`history`/`navigator`, `ResizeObserver`/`IntersectionObserver` (the engine calls `__observeCheck` from `Page::sync` only while `ScriptHost::observing()`), `fetch`/XHR. Requests go through the `Fetcher` trait (`nile-script/src/net.rs`; `LocalFetcher` by default, `PageFetcher` in nile-engine adds http via `ureq` behind the `net` feature), one worker thread each; `ScriptHost::tick` hands finished ones to `__fetchDone` and asks to be ticked every 16ms while any are pending. `EventTarget.dispatchEvent` already calls `on<type>` properties, don't call them yourself.
- `@nile` / `@env` modules (`@sciter` resolves to `@nile`, kept for Sciter apps): the resolver passes the names through and `FileLoader` declares tiny wrapper modules over `__sciterModule` / `__envModule` (defined at the end of `web.js`; OS access is the single `envCall` native in `envmod.rs`). Shapes follow docs.sciter.com/docs/JS.runtime (module-sciter, module-env).
- `border-radius` is `Corners` (px, clockwise from top left) plus `border_radius_pct` (fractions of the box's width/height); the renderer resolves both through `ComputedStyle::corner_radii(w, h)` into Skia's per-corner radii (`round_rect`). Inline decorations (`InlineDeco`) keep one uniform radius.
- Tables in the editor (`edit.js`): `insertTable`, `tabInTable`, `deleteAcrossCells`; `closestBlock` returns a `td`, so Enter (`splitBlock`) and Backspace/Delete (`backspace`) treat cells as walls. `Page::default_key` offers Tab to the host first.
- Rich clipboard: `Clipboard::{html, set_html}` (arboard on the system clipboard); the editor's copy asks `__selectionHtml` (via `Range.cloneContents`), paste sends HTML through `__editPasteHtml` -> `pastedBlocks` (the sanitiser: `PASTE_TAGS`, `PASTE_STYLES`, `SAFE_URL`) -> `pasteBlocks`, which splits the current block for multi-paragraph pastes. `call()` returns JSON, so strings need `unjson_string`.
- IME: `Page::{ime_wanted, ime_cursor_rect, ime_preedit, ime_commit, ime_cancel}`. In text inputs the composition is `View::preedit` (layout splices it into the displayed text in place of the selection via `LayoutOptions::preedit`, `Overlay::preedit` underlines it, the real value changes only on commit through `insert_text`); in contenteditable hosts it is an underlined `data-nile-ime` span managed by `__imePreedit`/`__imeCommit` in `edit.js` (not in undo history). Focus changes cancel it. winit's `Ime` events and `set_ime_allowed`/`set_ime_cursor_area` are in `App::sync_ime`.
- 3D transforms: `Affine` is a projective 3x3 (`g`, `h`, `i` are the perspective row); `Affine::from_style_in` builds a 4x4 (`M4`) from the `TransformFn` list, folds in the container's `perspective` (`parent_perspective`, stored as `LayoutBox::persp` so `refresh_paint` can re-bake) and flattens it to z = 0. `perspective` changes are layout-affecting in `same_layout` on purpose.
- Static positions: absolute boxes re-parented to a distant containing block are listed in `ABS_HANDED`; `compute_static_positions` (after layout, before `flatten`) turns the ones with `auto` insets into absolute page coordinates in `STATIC_AT`, which `flatten` uses instead of Taffy's (containing-block corner) position.
- Stacking contexts (`flatten`): a context (the root, or `forms_context`: positioned + `z-index`, flex/grid item + `z-index`, `opacity < 1`, `transform`, `fixed`) calls `collect_hoisted` to find the positioned/z-indexed descendants that belong to its paint order, records them in the `HOISTED` thread-local so their ancestors skip them, and emits them around the in-flow children by layer (negative z first, positive last). Descendants beneath a `confines` box (clip, opacity, transform, sticky) are never hoisted, because the flat paint list scopes clips and layers by subtree range. `paint_layer(style, flex_item)` is the single ordering rule.
- `table-layout: fixed`: `build_table` sets `grid_template_columns` (px / % / `minmax(0, 1fr)` per column from `<col>`s, else the first row) and clears the cells' own widths; only when the table's `width` isn't auto.
- Frames (`nile-engine/src/frames.rs`): `<frame>` (block) and `<iframe>` (inline-block) get a UA default size; the outer layout only sizes the box. `Page::update_frames` (cheap without frames: it rescans only when `Document::version` changes) loads a nested `Page` per element into `Page::frames` (`Rc<RefCell<Frames>>`, shared with the script functions), from `src` or `srcdoc` (what `loadHtml` sets; `nile-base` holds its base folder), refreshes its content-box rect, and emits `newdocument`/`complete`. `Page::paint` draws each nested page into a buffer and composites it over the rect (after everything else, so outer menus/fixed boxes can't cover it). Input is routed in `Page::{pointer_moved, press, release, wheel, key, default_key, insert_text, ime_*, cursor, take_file_request, tick}`: a press focuses and captures the frame under the pointer, keys go to the focused frame, a wheel the frame can't use falls through to the outer page; `with_frame` lends the outer clipboard and modifiers. The HTML parser drops `<frame>` outside a frameset, so `nile-dom` rewrites it to `<nile-frame>` (and back in `convert`). Scripts: `el.document` (a `FrameDocument` proxy: `$`, `$$`, `eval`, `call`, `title`), `url`, `loadFile`, `loadHtml`, `loadEmpty`, `frame` and `contentWindow` run code in the frame's own script context through the `__frameEval` host function (JSON in/out, so only plain data crosses); `frame.postMessage(data)` and `window.parent.postMessage(data)` are queued (`Frames::posts`, `FrameSlot::outbox`) and delivered by `Page::deliver_frame_messages` (called from `sync`/`tick`) as a `message` event with `data`/`source`. Frame pages are never borrowed while their own scripts call back out, which is why the bridge is queues plus `try_borrow_mut`.
- `<frameset cols|rows>` (+ `<splitter>`): `nile-dom` hides it from the HTML parser as `<nile-frameset>` (and closes `<splitter/>`); layout makes it a grid (`frameset_tracks`: `px`/`%`/`N*`/bare number per pane from the list, `SPLITTER` px per splitter child; any element is a pane). `Page::splitter_press`/`splitter_drag_to` (in `frames.rs`) resize by rewriting the `cols`/`rows` attribute (the dragged pane gets px, the pane after it too unless it is `*`), so the DOM stays the single source of truth; `el.frameset.state` reads pane sizes and sets the attribute. A frame's `content-style` CSS file is appended to the nested document as a final `<style>`. `html { height: 100% }` now resolves against the viewport (layout gives the root element a definite px height and extends `content_height` over the content, since the root no longer grows).
- `<include src media>`: `nile-dom/src/include.rs` expands it as *text* before parsing (so it works in `<head>` too); `Page::from_source` supplies the loader (files under the page's folder; a nested `src` is relative to the fragment naming it). A missing fragment or false `media` (`platform == "OSX"`, `!=`, `and`/`or`) keeps the element's own content as the fallback; depth limit 16 stops cycles.
- JSX is a source transform (`nile-script/src/jsx.rs`, a scanner, not a parser)
  applied to every script and module before QuickJS sees it; it returns `None`
  for non-JSX or malformed input so the engine reports the original error. Modules
  resolve relative to the importing file (inline modules are named
  `page.html#moduleN`).
- DOM wrappers in JS are keyed by arena id (`wrap(id)` in `prelude.js`); new
  DOM API usually means one small native in `lib.rs` plus a JS method.

- Taffy rounds layout to whole pixels. Final text line breaking uses
  `rect.width + 1.0` so rounding doesn't cause spurious wraps.
- The page's canvas background comes from `html`, else `body` (CSS rule),
  not from the body box.
- softbuffer wants 0RGB u32 pixels. Skia renders `BGRA8888` into the same
  bytes, which matches on little-endian (all targets we support).
- Selector matching is Servo's `selectors` crate (MPL-2.0 — keep it a separate
  dependency, don't copy its code). A rule whose selector list fails to parse is
  dropped whole. `ElementRef` in `nile-style/src/selector.rs` adapts the arena DOM.
- Inline padding/border become no-break-space "spacer" runs sized via the font's
  NBSP advance (`TextEngine::nbsp_ratio`), not Parley inline boxes: Parley always
  allows a wrap after an inline box, which strands the spacer from its word.

- Style values: `parse.rs` evaluates `@media` and `vw`/`vh` at parse time against the viewport
  (`compute_styles_in`; `StyleMap::uses_viewport` tells the shell to restyle on resize). Custom
  properties and `var()` keep the source text in `Declaration::raw` and are resolved per element in
  the cascade (`substitute`). `!important` is a stable sort of the collected declarations.
  `examples/css-compat.html` is the visual conformance page; green = works. `calc()` mixing `%` and
  `px` becomes `Length::Calc` and is resolved by `resolve_calcs` in layout after a first pass (Taffy's
  own calc hook is a stub in `TaffyTree`). Animation: the cascade yields target styles (`ComputedStyle::{transitions, animations}`, `StyleMap::keyframes`); the shell's `View` keeps them as `base`, owns an `Animator` (nile-style/src/anim.rs) and a clock, and overwrites `styles` with in-between values on each restyle (`adopt`, starts transitions) and each 16ms tick (`animate`) while `Animator::is_active`. Times are seconds; tests call `Animator::update` with explicit times. `transform` becomes `LayoutBox::transform` (an `Affine` in layout coordinates with the origin folded in); `placements()` composes it with scroll translations into `Placement::xf`, which hit testing, `node_rect_scrolled` and text-index lookups use, and the renderer `concat`s it around the box's subtree. Never read scroll shifts as plain dx/dy any more. Images: the embedder gives layout an `ImageLoader` (`LayoutOptions::images`; the shell uses `FileImages` on the page's folder). Layout only needs sizes (`imagesize`), loads what the document and styles name up front into a thread-local, and puts the encoded `ImageData` on `LayoutBox::{image, bg_image}`; the renderer decodes with Skia and caches by `ImageData::id`. `<img>` is a `NodeCtx::Replaced` Taffy leaf. Grid properties live in `nile-style/src/grid.rs` (`Value::{Fr, Slash, Minmax, Repeat}` from the parser; `grid-area` names resolved to line numbers in layout's `place_in_area`); layout maps them straight onto Taffy's grid style. Absolute boxes are re-parented in the Taffy tree to their nearest positioned ancestor (`with_containing_block`/`hand_off_absolute`, thread-locals in `nile-layout`; the root is the fallback), and `flatten` sorts siblings into paint order by `z-index` (`paint_layer`). Gradients are `Value::Gradient` -> `ComputedStyle::background_image` (stops resolved by `Gradient::resolved_stops`); the renderer's `gradient_shader` builds the Skia shader. `::before`/`::after` are "generated boxes": the cascade (`pseudo_style`, matched in `ForStatelessPseudoElement` mode) appends their styles to `StyleMap::styles` under ids past the document's nodes, with `StyleMap::{pseudo, origin, content, is_pseudo}`. Layout's `kids()` puts them around an element's children; `hit_test` and text owners map back to the element, and `node_rect`/the index skip them. Never call `doc.node()` on a box id without checking `styles.is_pseudo`. `opacity < 1` wraps the element's paint-list range `[i, subtree_end)` in a `save_layer_alpha`. Borders are per side (`border_color`, `border_style`,
  `border_width`); `border_color_set` holds what the author set, `None` = currentColor.
